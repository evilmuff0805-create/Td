## 1. 플레이 방향

**영웅은 선택한 타일에 자리 잡고 자동으로 싸운다. 플레이어는 배치·재배치·건설·강화·스킬에 집중한다.**

자유 이동 패드는 **영웅을 누른 채 드래그 → 빈 공용 타일 위에서 놓기**로 대체한다. PC도 마우스로 같은 조작을 한다. 영웅과 건물이 한정된 배치 자리를 나눠 쓰므로 영웅의 위치 자체가 건물 배치와 연결된 전략적 선택이 된다.

현재 확정된 캐릭터·건물 일러스트, 사계절, 높은 고정 시점, 작은 건물과 일정한 강화 단계별 크기는 이어 쓴다. 평소에는 바닥에 작은 자리 표식만 보이고 배치·재배치 때 가능한 칸의 테두리와 사거리를 강조한다. 전장 전체를 진한 격자로 덮지 않는다.

세로 휴대폰에서 주요 배치 구역과 적의 흐름이 기본 시점에 읽혀야 한다. 현재 넓은 지도의 모든 칸을 작은 버튼처럼 노출하지 않는다. 필요하면 전투 구역·길 배치를 압축하고 배경 장식은 바깥에 배치한다. 타일 수는 실제 터치 크기와 사거리 검증 후 확정한다.

## 2. 지도와 배치 타일

| 구역 | 규칙 제안 |
|---|---|
| 적 이동로 | 적은 정해진 길로 이동해 성문에 도달한다. 건설할 수 없다. |
| 공용 배치 타일 | 지정한 건설 터 한 칸에 **영웅1명 또는 유산1개**만 배치한다. 같은 칸에 둘을 겹쳐 놓을 수 없다. |
| 배경·물·장식 | 조작 대상이 아니다. 빈 배경을 눌렀다고 건설 메뉴가 뜨지 않는다. |

배치 타일은 적 이동로 밖에 두고 **모든 영웅과 건물이 같은 타일 집합**을 사용한다. 근접·원거리별 전용 타일과 길 위 영웅 저지 타일을 두지 않는다. 영웅을 드래그하는 동안 빈 타일을 강조하고, 건물·다른 영웅·사망 영웅 예약 타일은 배치 불가로 표시한다.

배치 타일이 총N칸이면 **영웅1명일 때 건물 최대N−1개, 영웅2명일 때 최대N−2개**다. 예를 들어10칸이면 솔로1영웅+건물9개, 온라인2영웅+건물8개가 최대다. 영웅이 한 명 늘면 건물을 하나 덜 지을 수 있다는 뜻이며10칸은 설명용 숫자다. 현재 출전 인원 정책은 그대로이고, 솔로 추가 영웅 소환·해금은 이번 수정에 포함하지 않는다.

생존·사망 여부와 관계없이 출전 영웅은 한 칸을 차지한다. 영웅이 쓰러져도 건물 자리가 늘어나지 않는다. 지도 시작 전에 출전 영웅 수만큼 서로 다른 유효 초기 타일이 있는지 검사하고, 부족한 지도 설정은 전투 시작 전에 거부한다.

온라인 두 영웅의 최초 타일을 서로 다르게 배정하고, 시작 전 드래그로 위치를 조정한다. 자동으로 비워 두는 추가 예약 칸은 만들지 않는다. 배치 자리가 모두 차면 빈칸으로 재배치할 수 없으며, 건물 소유자가 직접 철거해 자리를 확보하는 선택이 필요하다. 점유된 칸으로 드래그해도 자동 철거·교환·동료 영웅 이동은 일어나지 않는다.

한 칸 한 개체는 **영웅·건물의 고정 배치 슬롯**에 대한 규칙이다. 적·병영 병사·의병·목책 등 전투 개체의 길 위 동시 존재를 금지하는 규칙이 아니다. 이들의 기존 소환·길 위 저지는 유지한다. 각 타일에는 장식과 건물 외형을 포함해 겹치지 않는 터치 영역이 필요하며, 합격기 거리·유산 시너지·공격 사거리 안에 유효한 배치 조합이 있어야 한다.

## 3. 모바일·PC 조작

| 행동 | 제안 흐름 |
|---|---|
| 영웅 최초 배치 | 준비 상태에서 공용 타일에 영웅이 보인다. 드래그로 빈 타일에 옮긴 뒤 웨이브를 시작한다. |
| 영웅 재배치 | 내 영웅을 누른 채 드래그 → 빈 공용 타일에서 놓기. 미리보기·사거리·가능/불가 표식을 제공한다. 건물에 가려졌으면 내 영웅 초상화에서도 드래그를 시작한다. |
| 건설 | 빈 공용 타일 터치 → 하단 건물 목록 → 가격 확인 후 건물 선택. 영웅이 있는 타일에서는 건설하지 않는다. |
| 강화·매각 | 건물 탭 → 같은 하단 패널에서 강화·최종 A/B·매각. |
| 스킬 | 현재처럼 버튼 → 대상 지정. 영웅 재배치·건설 선택과 동시에 활성화되지 않는다. |
| 취소 | 드래그는 잘못된 곳에서 놓거나 포인터 취소 시 원래 타일로 복귀한다. 건설·스킬 선택은 취소 버튼 또는 배경 탭으로 닫는다. |
| 카메라 | 전장 안의 두 손가락 제스처와 기본 시점 복귀를 유지한다. 제스처 후 남은 손가락이 건설·재배치로 이어지지 않게 한다. |

건물 종류가 많아도 원형 메뉴가 전장을 덮지 않도록 **하단 선택 패널**을 추천한다. 목록 스크롤은 카메라 제스처와 구분한다. 강화 단계는 기존 건물 바로 아래 네 점으로 표시하고 연결선을 추가하지 않는다.

자기 영웅 또는 자기 영웅 초상화에서 시작한 포인터만 영웅 드래그 후보가 된다. 영웅을 살짝 누르기만 한 경우와 드래그를 구별하는 작은 이동 임계값을 둔다. 드래그 중 손가락이 캐릭터와 목적지를 가리지 않게 미리보기 위치를 보정한다. 승인 전 실제 영웅은 원래 타일에서 전투하고 미리보기만 따라간다. 놓은 뒤 승인된 위치로 착지하며 드래그 동안 무적·공격 정지·점유 해제가 생기지 않는다.

호스트 명령을 전송하기 전에는 배경·HUD·점유된 타일 위 놓기, `pointercancel`, 두 번째 손가락 등장, 앱 전환·회전·연결 대기·전투 종료가 미리보기만 취소한다. 취소 뒤 클릭이 건설이나 스킬로 이어지지 않게 한다. 원본 타일·체력·군자금·재배치 대기시간은 보존한다.

**유효 드롭을 이미 전송한 뒤에는 호스트 승인/거절 결과를 따른다.** 이때의 앱 전환·회전을 무조건 무변경 취소로 취급하지 않는다. 복귀하면 승인된 전투 상태를 동기화하고, 영웅당 승인 대기 요청은 하나만 허용하며 요청ID로 같은 드롭의 중복 처리를 막는다. 승인 전 타일을 미리 비우거나 대기시간을 소모하지 않는다.

스킬 조준 중에는 기술 대상 입력이 우선이며 영웅 드래그를 시작하지 않는다. 조준을 취소한 뒤 드래그한다. 드래그와 카메라 이동은 동시에 실행하지 않고, 두 손가락 전환 시 진행 중인 드롭 전 미리보기를 취소한다. 취소된 손가락의 후속 클릭도 소비한다.

PC도 동일한 타일 규칙으로 작동한다. 우클릭 자유 이동과 길 클릭 이동은 더 이상 전투 명령이 아니며 기술 단축키는 유지한다. 도움말·튜토리얼도 함께 바꾼다.

## 4. 전투와 영웅 역할

- 기본 공격은 자동, 기술·궁극기·비기는 수동으로 유지한다. 모든 영웅은 배치한 공용 타일에서 적을 바라보고 싸우며 타일 밖 자동 추격이나 직접 몸으로 적을 막는 행동을 하지 않는다.
- **기존 근접 영웅도 무기 휘두르기 → 검기·창기·충격파 발사 → 실제 비행 → 착탄 피해**로 바꾼다. 장식 효과만 추가하는 방식이 아니라 사거리·발사 시점·대상·탄속·착탄 판정을 연결한다. 시전 순간 피해를 주고 나중에 투사체만 도착하는 불일치를 만들지 않는다. 일반 공격·패시브·기술 설명과 원화를 함께 점검한다. 영웅마다 단일/직선/범위와 피해·공격 주기를 검증하고 모두 같은 원거리 공격으로 획일화하지 않는다.
- 강감찬은 별빛 검기와 적장 집중 타격, 권율은 창기·충격파와 방어·통제 역할을 후보로 둔다. 색·모양·공격 자세를 구분하고 좁은 화면에서 길과 적을 가리는 이펙트 밀도를 제한한다. 새 공격의 사거리·피해·관통·범위 수치는 아직 확정하지 않았다.
- 준비 중에는 자유롭게 재배치한다. 웨이브 중에는 군자금을 소비하지 않는 재배치와 짧은 재사용 대기시간을 제안한다. 초기 비교값은3초이며 실제 플레이로 확정할 값이다.
- 호스트가 승인한 게임 틱에 목적지 점유·출발지 해제·영웅 위치·재배치 대기시간을 원자적으로 변경한다. 연출은 승인된 상태를 따라가고 별도 판정을 만들지 않는다. 거절되면 위치·점유·대기시간 모두 그대로다. 대기시간은 배속·일시정지를 따르는 게임 시간 기준이다.
- 재배치로 체력·공격 주기·스킬 대기시간·버프·피격 기록·회복 대기시간이 초기화되지 않는다. 재배치 자체에 무적은 없다. 영웅을 대상으로 이미 발사된 추적 투사체는 같은 영웅ID를 추적하고, 영역 공격은 발동 틱의 실제 위치로 판정하는 안을 기본으로 비교한다. 반복 재배치가 무한 생존을 만들지 않는지 검증한다.
- **영웅 직접 저지는 제거한다.** 권율의 기존3명 저지 특성은 둔화·방어지원 등 역할을 살리는 대체 효과를 검토한다. 영웅 체력·피격·사망·회복은 유지하며, 병영 병사·의병·목책의 저지는 바꾸지 않는다. 영웅 직접 저지 제거와 원거리 공격 추가로 난이도가 서로 다른 방향으로 변하므로 효과를 함께 검증한다.
- 병영·의병·목책을 선택하지 않은 편성도 방어 가능한지 확인한다. 권율의 대체 특성은 부산진 비교 시험 후 확정하며, 기존 보통 솔로 영웅 피해1.5배 보정도 새 공격·배치 방식에 맞춰 재검증한다. 온라인은 영웅 두 명이 건물 두 자리를 사용하는 상태로 난이도를 검증한다.
- **강감찬 돌진**은 현재 실제 영웅 좌표를 바꾸므로 별도 수정이 필요하다. 영웅은 배치 타일에 남고 지정 방향으로 직선 돌격파·검기를 보내 피해와 제어 효과를 주는 안을 후보로 둔다. 시각 효과만 타일 밖으로 나가고 영웅의 점유·위치·피격 기준은 타일에 남는다. 기존 수치와 동일한 체감이라고 가정하지 않는다.
- **곽재우의 기동성**은 자유 이동 속도가 없어지는 만큼 재배치 대기시간 우대 등으로 보존하는 안을 비교한다. 수치 확정은 밸런스 검증 뒤로 둔다.
- 이순신 부채꼴 방향, 원거리 사거리, 주변 유산 강화, 은신 탐지, 범위 지원, 길 위 소환, 합격기를 새 배치 위치에서 확인한다. 배치 변경으로 합격기 거리 조건을 충족하지 못하는 지도가 생기지 않게 한다.
- 사망 영웅의 타일은 예약하고 그 타일에서 부활하는 안을 기본으로 삼는다. 현재 자연 부활은 성문 근처로 이동하고 동의보감·단군/세종 합격기는 사망 위치에서 즉시 부활하므로 **모든 부활 경로를 예약된 배치 타일로 통일**한다. 사망 중 이동은 막고 부활 직후의 저지·피격을 검증한다.

이번 설계는 한 사람이 영웅 여러 명을 소환·합성하는 시스템까지 포함하지 않는다. 영웅1명으로도 배치와 스킬의 선택이 재미있는지 먼저 확인한다.

## 5. 협동과 기록 보존

솔로1명/1영웅, 온라인2명/각1영웅, 서로 다른 영웅 선택, 방 만들기·참가, 독립 군자금, 합격기를 이어 쓴다. 재화·해금·강화·의상·도감·전장 성적을 초기화하지 않는다.

타일은 두 사람이 공유하고 영웅·건물 모두 같은 점유 검사에 참여한다. 영웅 조작은 본인만 가능하다. 현재처럼 동료 건물에도 자기 군자금으로 공동 강화하고, 철거는 소유자가 실행하며 환급은 기여자에게 돌아가는 정책을 보존한다. 같은 빈 타일로 두 영웅이 드래그하거나 영웅 드롭과 건설이 경합하면 호스트가 먼저 유효하게 처리한 명령만 승인한다. 거절된 건설은 군자금을 차감하지 않고 거절된 드롭은 원래 타일과 대기시간을 보존한다.

타일ID·점유·소유자·재배치 대기시간·사망 예약을 전투 상태와 재접속 상태에 포함한다. 기존 `h.slot`은 편성 순서이므로 별도 `deploymentSlotId`를 사용한다. 화면의 좌표만 칸에 맞추는 것으로 완료하지 않는다. 호스트가 타일 존재·배치 자격·점유·생존·대기시간·소유권을 검사하고 성공/실패를 응답한다. 구버전 자유 이동 명령을 거부하고 방의 규칙 버전과 배치 지도 버전을 확인해 구버전·신버전 혼합 출전을 막는다.

일시적 끊김의 정지·재접속, 호스트 백그라운드 대기, 영구 이탈 시 보상·인계 없이 종료하는 현재 정책을 유지한다.

## 6. 구현 착수 후 단계

1. **규칙 명세와 시제품 승인**: 공용 타일·영웅/건물 점유·드래그·준비/전투 재배치·무기 발사 공격·돌진/기동성·사망 예약을 명시하고 아스트라 리스크 검토를 받는다. 이번 계획 수정 요청을 전체 구현 승인으로 취급하지 않는다.
2. **부산진1전장 시제품**: 공용 타일·영웅 드래그·건설/강화 하단 패널을 만든다. 이순신의 기존 원거리 공격과 강감찬·권율의 새 무기 발사 공격, 영웅 수에 따른 건설 한도를 비교한다. 기본 세로 화면에서 읽히는 전장 배치를 잡는다.
3. **모바일 플레이 확인과 협동 검증**: 손가락 크기·드래그 취소·사거리·착탄·전장 가림을 확인하고 사용자 플레이 피드백을 받는다. 실제 호스트/게스트로 드롭/건설 동시 경합·각자 영웅·군자금·공동 강화·사망 예약·재접속을 검증한다.
4. **영웅8명과 캠페인25전장 확대**: 각 전장의 공용 타일·길·강화 시너지·제어 기술·보스 대응을 재설계한다. 곽재우의 기동성 대체와 합격기 배치도 확인한다. 분기 길·해전·겨울·최종 전장을 대표 검증한 후 전체 전장과 성장 경로를 확인한다.
5. **최종 검수와 공개 반영**: 아스트라가 검증 결과와 남은 위험을 검토한 뒤 승인한 빌드를 같은 Railway 서버에 반영한다. 배포 전까지 현재 공개 버전을 유지하고 복구 가능한 기준 커밋을 남긴다.

## 8. 현재 결론

수정안은 **영웅·건물 공용 타일 + 영웅 드래그 재배치 + 무기에서 발사되는 원거리 공격 + 하단 건설/강화 패널**이다. 영웅 한 명이 건물 한 자리와 같은 배치 자원을 사용한다. 기존 미감을 이어 쓰면서 배치·건설·스킬에 집중하는 모바일 디펜스로 정리한다.

먼저 부산진 시제품으로 조작과 전투를 확인한 뒤 전체 전장으로 확대한다. 이 문서는 승인 전 계획과 검토 이력을 보존한다. 이후 사용자 구현 승인과 실제 작업 결과는 [공용 타일 구현 기록](TILE_BOARD.md)에 별도로 기록한다.

## 아스트라 계획 검토 이력

2026-10-18 아스트라의v1 검토는 길 위 저지 타일·길 옆 사격/지원 타일·별도 건설 타일 안에 대한 의견이었다. 해당 분리 배치 추천은 사용자의 최신 수정으로 대체됐으며v2의 승인으로 취급하지 않는다. v1에서 제안된 다음 공통 조건은 수정안에서도 이어 쓴다.

1. 배치 슬롯 점유와 적/소환물 공존의 구분, 온라인2명 및 합격기 가능 자리.
2. 승인 틱의 원자적 재배치, 실패 시 상태 보존, 게임 시간 대기시간과 전투 타이머 보존.
3. 자연·보급품·합격기 부활의 예약 타일 정책 통일.
4. 강감찬 돌진·곽재우 기동성 재설계와 기존 공동 건물 강화/정산 정책 보존.
5. 별도 배치 슬롯ID, 스냅샷 포함, 호스트 검증과 배치 지도 버전 확인.

같은 날 아스트라가 사용자의v2 수정 규칙을 다시 검토하고 사용자 지시와 일치한다고 확인했다. 다음5가지 보완 의견을 본문에 반영했다.

1. 무기 발사 연출과 실제 비행/착탄 판정, 일반 공격·패시브·설명 동시 점검.
2. 영웅 직접 저지 제거의 방어 공백, 저지 병력이 없는 편성, 보통 솔로1.5배 보정·온라인 건물 감소 재검증.
3. 사망 중에도 영웅 한 칸 점유, 초기 배치 불가 지도 거부, 만석 때 재배치 제한 안내.
4. 자기 영웅에서 시작한 드래그, 기술/카메라 우선순위, 가려진 영웅의 초상화 드래그.
5. 드롭 전 취소와 전송 후 승인 대기의 구분, 영웅당 하나의 요청, 요청ID 중복 방지와 복귀 동기화.

아스트라의v2 결론도 **설계 검토 의견이며 구현·배포 승인이 아니다.** 현재 공개 게임과 실행 코드는 그대로다.

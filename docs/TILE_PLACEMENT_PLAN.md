# 영웅 타일 배치형 모바일 디펜스 전환 계획

2026-10-18 · **설계 제안 / 구현·배포 전**

사용자 요청: 자유롭게 움직이던 영웅을 「협타디: 협동 타워 디펜스」처럼 정해진 타일에 배치하는 방식으로 바꾸고, 모바일 건설 조작을 단순하게 한다. 이번 요청은 계획 수립까지이며 게임 코드와 공개 버전은 변경하지 않는다.

참고 게임의 이름과 간단한 조작·협동 중심 방향은 [공식 Google Play 소개](https://play.google.com/store/apps/details?id=com.percent.aos.cooptd&hl=ko)에서 확인했다. 아래 타일 종류·재배치·스킬·협동 규칙은 호국영웅전에 맞춘 **제안**이며 참고 게임의 세부 규칙을 확인·복제했다고 주장하지 않는다.

기준: 기록 커밋 `24af405`, 공개 구현 커밋 `914386d`. 기존 지도는 24×14칸이며 캠페인25전장·영웅8명·유산10종이다. 솔로1영웅과 방 코드 협동 각자1영웅을 유지하는 전제로 계획한다.

## 1. 플레이 방향

**영웅은 선택한 타일에 자리 잡고 자동으로 싸운다. 플레이어는 배치·재배치·건설·강화·스킬에 집중한다.**

자유 이동 패드는 타일 재배치 조작으로 대체한다. 길을 따라 직접 걷게 하는 방식보다, 내 영웅 선택 → 재배치 → 가능한 타일 선택으로 완결되는 방식을 추천한다. 드래그는 선택 기능으로만 검토하고 필수 조작으로 두지 않는다.

현재 확정된 캐릭터·건물 일러스트, 사계절, 높은 고정 시점, 작은 건물과 일정한 강화 단계별 크기는 이어 쓴다. 평소에는 바닥에 작은 자리 표식만 보이고 배치·재배치 때 가능한 칸의 테두리와 사거리를 강조한다. 전장 전체를 진한 격자로 덮지 않는다.

세로 휴대폰에서 주요 배치 구역과 적의 흐름이 기본 시점에 읽혀야 한다. 현재 넓은 지도의 모든 칸을 작은 버튼처럼 노출하지 않는다. 필요하면 전투 구역·길 배치를 압축하고 배경 장식은 바깥에 배치한다. 타일 수는 실제 터치 크기와 사거리 검증 후 확정한다.

## 2. 지도와 배치 타일

| 구역 | 규칙 제안 |
|---|---|
| 적 이동로 | 적은 정해진 길로 이동해 성문에 도달한다. 건설할 수 없다. |
| 영웅 배치 타일 | 명시적으로 지정한 칸만 영웅 배치·재배치가 가능하다. 한 칸에 영웅1명. |
| 건설 타일 | 지정한 터 한 곳에 유산1개를 건설한다. 영웅 재배치와 구별한다. |
| 배경·물·장식 | 조작 대상이 아니다. 빈 배경을 눌렀다고 건설 메뉴가 뜨지 않는다. |

초기안은 **근접 영웅용 길 위 저지 타일과 원거리·지원 영웅용 길 옆 타일**로 배치 자격을 나눈다. 강감찬·권율을 길 위 저지 지점에 배치하면 기존 근접 공격과 저지 계산을 가장 많이 재사용할 수 있다. 영웅을 고르면 그 영웅이 설 수 있는 타일만 강조한다. 이 자격 구분은 시제품 규칙이며 모든 영웅의 모든 타일 배치를 허용하는 안은 첫 시제품의 기본안으로 삼지 않는다.

온라인에는 각 영웅 조합이 출발할 수 있는 두 자리와 재배치 여유 자리가 필요하다. 근접2명·원거리2명·혼합 조합, 합격기 거리 안의 유효 배치를 지도별로 검사한다. 한 칸 한 개체는 **영웅·건물의 고정 배치 슬롯**에 대한 규칙이다. 적·병영 병사·의병·목책 등 전투 개체의 길 위 동시 존재를 금지하는 규칙이 아니다.

길 옆 타일에 서 있는 영웅이 떨어진 길에서 적을 막게 하는 방식은 별도 공격·피격·거리 규칙이 필요하다. 시제품에서는 길 위 저지 타일을 우선 검증하고, 미감이나 터치 판독 문제가 확인될 때 대안을 비교한다. 사거리만 늘려 해결하지 않는다.

건설 타일과 영웅 타일을 분리하면 이동과 건설의 충돌, 같은 칸 점유, 큰 건물에 가려지는 영웅 문제를 줄일 수 있다. 모든 타일은 장식과 건물 외형을 포함해 겹치지 않는 터치 영역을 가져야 한다.

## 3. 모바일·PC 조작

| 행동 | 제안 흐름 |
|---|---|
| 영웅 최초 배치 | 준비 상태에서 기본 타일에 영웅이 보인다. 원하는 영웅 타일을 선택해 위치를 바꾼 뒤 웨이브를 시작한다. |
| 영웅 재배치 | 내 영웅 또는 초상화 → 재배치 → 표시된 빈 영웅 타일 탭. 목적지와 사거리를 먼저 확인한다. |
| 건설 | 빈 건설 타일 → 하단 건물 목록 → 가격 확인 후 건물 선택. |
| 강화·매각 | 건물 탭 → 같은 하단 패널에서 강화·최종 A/B·매각. |
| 스킬 | 현재처럼 버튼 → 대상 지정. 영웅 재배치·건설 선택과 동시에 활성화되지 않는다. |
| 취소 | 취소 버튼 또는 조작 대상이 아닌 배경 탭. 실행된 건설·스킬을 취소하는 의미는 아니다. |
| 카메라 | 전장 안의 두 손가락 제스처와 기본 시점 복귀를 유지한다. 제스처 후 남은 손가락이 건설·재배치로 이어지지 않게 한다. |

건물 종류가 많아도 원형 메뉴가 전장을 덮지 않도록 **하단 선택 패널**을 추천한다. 목록 스크롤은 카메라 제스처와 구분한다. 강화 단계는 기존 건물 바로 아래 네 점으로 표시하고 연결선을 추가하지 않는다.

PC도 동일한 타일 규칙으로 작동한다. 우클릭 자유 이동과 길 클릭 이동은 더 이상 전투 명령이 아니며 기술 단축키는 유지한다. 도움말·튜토리얼도 함께 바꾼다.

## 4. 전투와 영웅 역할

- 기본 공격은 자동, 기술·궁극기·비기는 수동으로 유지한다. 배치 위치에서 적을 바라보고 싸우되 임의로 타일 밖의 적을 추격하지 않는다.
- 준비 중에는 자유롭게 재배치한다. 웨이브 중에는 군자금을 소비하지 않는 재배치와 짧은 재사용 대기시간을 제안한다. 초기 비교값은3초이며 실제 플레이로 확정할 값이다.
- 호스트가 승인한 게임 틱에 목적지 점유·출발지 해제·저지 해제·영웅 위치·재배치 대기시간을 원자적으로 변경한다. 연출은 승인된 상태를 따라가고 별도 판정을 만들지 않는다. 거절되면 위치·점유·대기시간 모두 그대로다. 대기시간은 배속·일시정지를 따르는 게임 시간 기준이다.
- 재배치로 체력·공격 주기·스킬 대기시간·버프·피격 기록·회복 대기시간이 초기화되지 않는다. 재배치 자체에 무적은 없다. 영웅을 대상으로 이미 발사된 추적 투사체는 같은 영웅ID를 추적하고, 영역 공격은 발동 틱의 실제 위치로 판정하는 안을 기본으로 비교한다. 반복 재배치가 무한 생존을 만들지 않는지 검증한다.
- 강감찬·권율의 저지 수와 공격·피격은 실제 길 위 저지 지점에서 계산한다. 재배치·사망 때 잡고 있던 적을 풀어야 한다.
- **강감찬 돌진**은 현재 실제 영웅 좌표를 바꾸므로 별도 수정이 필요하다. 배치 타일을 유지한 채 지정 방향을 타격하고 돌아오는 돌격 연출을 후보로 둔다. 타격 구간은 출발 타일과 지정한 유효 목표로 정하고, 시전 중 저지를 잠시 해제하는 시간·피격·다시 저지를 시작하는 시점을 명세한다. 장면의 임의 좌표를 새 배치 위치로 쓰지 않는다. 기존 수치와 동일한 체감이라고 가정하지 않는다.
- **곽재우의 기동성**은 자유 이동 속도가 없어지는 만큼 재배치 대기시간 우대 등으로 보존하는 안을 비교한다. 수치 확정은 밸런스 검증 뒤로 둔다.
- 이순신 부채꼴 방향, 원거리 사거리, 주변 유산 강화, 은신 탐지, 범위 지원, 길 위 소환, 합격기를 새 배치 위치에서 확인한다. 배치 변경으로 합격기 거리 조건을 충족하지 못하는 지도가 생기지 않게 한다.
- 사망 영웅의 타일은 예약하고 그 타일에서 부활하는 안을 기본으로 삼는다. 현재 자연 부활은 성문 근처로 이동하고 동의보감·단군/세종 합격기는 사망 위치에서 즉시 부활하므로 **모든 부활 경로를 예약된 배치 타일로 통일**한다. 사망 중 이동은 막고 부활 직후의 저지·피격을 검증한다.

이번 설계는 한 사람이 영웅 여러 명을 소환·합성하는 시스템까지 포함하지 않는다. 영웅1명으로도 배치와 스킬의 선택이 재미있는지 먼저 확인한다.

## 5. 협동과 기록 보존

솔로1명/1영웅, 온라인2명/각1영웅, 서로 다른 영웅 선택, 방 만들기·참가, 독립 군자금, 합격기를 이어 쓴다. 재화·해금·강화·의상·도감·전장 성적을 초기화하지 않는다.

타일은 두 사람이 공유한다. 영웅 조작은 본인만 가능하다. 현재처럼 동료 건물에도 자기 군자금으로 공동 강화하고, 철거는 소유자가 실행하며 환급은 기여자에게 돌아가는 정책을 보존한다. 같은 빈 타일을 동시에 선택하면 호스트가 먼저 유효하게 처리한 명령만 승인하고, 거절된 건설은 군자금을 차감하지 않는다.

타일ID·점유·소유자·재배치 대기시간·사망 예약을 전투 상태와 재접속 상태에 포함한다. 기존 `h.slot`은 편성 순서이므로 별도 `deploymentSlotId`를 사용한다. 화면의 좌표만 칸에 맞추는 것으로 완료하지 않는다. 호스트가 타일 존재·배치 자격·점유·생존·대기시간·소유권을 검사하고 성공/실패를 응답한다. 구버전 자유 이동 명령을 거부하고 방의 규칙 버전과 배치 지도 버전을 확인해 구버전·신버전 혼합 출전을 막는다.

일시적 끊김의 정지·재접속, 호스트 백그라운드 대기, 영구 이탈 시 보상·인계 없이 종료하는 현재 정책을 유지한다.

## 6. 구현 착수 후 단계

1. **규칙 명세와 시제품 승인**: 영웅 타일 종류·점유·준비/전투 재배치·돌진/기동성·사망 예약을 명시하고 아스트라 리스크 검토를 받는다. 이번 계획 요청을 전체 구현 승인으로 취급하지 않는다.
2. **부산진1전장 시제품**: 타일 표시·영웅 배치/재배치·자동 전투·건설/강화 하단 패널을 만든다. 우선 이순신·권율로 원거리와 저지를 비교하고 강감찬·곽재우의 특수 동작을 검증한다. 기본 세로 화면에서 읽히는 전장 배치를 잡는다.
3. **모바일 플레이 확인과 협동 검증**: 손가락 크기·오입력·사거리·전장 가림을 확인하고 사용자 플레이 피드백을 받는다. 실제 호스트/게스트로 동일 타일 경합·각자 영웅·군자금·공동 강화·재접속을 검증한다.
4. **영웅8명과 캠페인25전장 확대**: 각 전장의 배치 타일·길·강화 시너지·근접 저지·보스 대응을 재설계한다. 분기 길·해전·겨울·최종 전장을 대표 검증한 후 전체 전장과 성장 경로를 확인한다.
5. **최종 검수와 공개 반영**: 아스트라가 검증 결과와 남은 위험을 검토한 뒤 승인한 빌드를 같은 Railway 서버에 반영한다. 배포 전까지 현재 공개 버전을 유지하고 복구 가능한 기준 커밋을 남긴다.

현재525개/40검사군은 기존 배포의 검증 기록이다. 새 타일 방식의 완료 근거가 아니다. 실제 휴대폰과 두 기기 네트워크 검수가 빠지면 그 항목은 미완료로 기록한다.

## 8. 현재 결론

추천안은 **영웅1명 타일 배치 + 자동 공격 + 탭 재배치 + 별도 건설 타일 + 하단 건설/강화 패널**이다. 기존 미감을 이어 쓰면서 모바일에서 이동과 건설을 혼동하던 원인을 줄인다.

먼저 부산진 시제품으로 조작과 전투를 확인한 뒤 전체 전장으로 확대한다. 이 문서는 계획이며, 아직 타일 방식의 게임 구현·밸런스 승인·배포는 하지 않았다.

## 아스트라 계획 검토

2026-10-18 기존 본부장 검토 역할의 아스트라가 읽기 전용으로 코드와 초안을 검토했다. 길 위 저지 타일·길 옆 사격/지원 타일·별도 건설 타일의 부산진 시제품을 추천했으며, 위 계획에 다음 조건을 반영했다.

1. 타일별 영웅 자격, 배치 슬롯 점유와 적/소환물 공존의 구분, 온라인2명 및 합격기 가능 자리.
2. 승인 틱의 원자적 재배치, 실패 시 상태 보존, 게임 시간 대기시간과 전투 타이머 보존.
3. 자연·보급품·합격기 부활의 예약 타일 정책 통일.
4. 강감찬 돌진·곽재우 기동성 재설계와 기존 공동 건물 강화/정산 정책 보존.
5. 별도 배치 슬롯ID, 스냅샷 포함, 호스트 검증과 배치 지도 버전 확인.

아스트라의 이번 결론은 **설계 검토 의견이며 구현·배포 승인이 아니다.** 현재 공개 게임과 실행 코드는 그대로다.
